交付不算完成：套用並驗證才銷帳

給你的 AI：本篇另備乾淨 Markdown 的 agent 版，讀了就能照著做——中文版・English

前段：寫給人看的故事

檔案寄到了，訊息寫著「做好了」，任務看起來就該結束。但過了幾天才發現：那份做好的東西從來沒有進到它該去的地方——程式碼沒有合進正式版本、文件沒有寫進線上產品、修法只躺在交付包裡，產品本身一點都沒變。更麻煩的是，帳面上它早就被標成「完成」，沒有任何清單還在追它，於是這件工作就這樣蒸發：有人做了、有人交了、帳也銷了，只有成果不存在。

這是協作流程裡最安靜的一種遺失：不是沒人做，而是「做完」這個詞被用在太早的位置。交付只是東西離開生產者的手；套用是它真的進到目標位置；驗證是有人回到目標位置本身實查它在不在、對不對；銷帳是這三步都過了之後，才准在帳本上寫下的那一筆。四個詞混成一個「完成」，中間任何一步掉下去，都不會有人發現——因為帳已經銷了，系統會以為這件事不存在了。

這篇的定版處置分三段。釘住：凡是交付了但還沒套用的東西，一律進「待套用」清單釘住追蹤，帳不准銷，清單上有名有主有期限。驗證：套用了不算數，要回到線上目標本身讀回、對照、實測，過了才算；驗證不過就當場退回開修訂單，不准先銷帳再說。升級：超過期限還沒套用，清單自己把這件事往上送，不靠任何人想起來追。

後段把整套判定寫死：六種處置代碼與優先序、什麼證據才叫套用證據、為什麼「他說做好了」永遠不是銷帳依據。任何人（或任何 AI）拿到一個交付情境，都能給出唯一處置，不靠猜。

以下為完整 runbook

1. 四個詞：交付、套用、驗證、銷帳

  • 交付：生產者把成品交出來，並自報完成。交付只證明東西離開了生產者的手，不證明它到了任何地方。
  • 套用：成品真的被寫入、合併或部署進任務單上指名的目標位置（正式版本、線上頁面、產品設定），而且留有套用證據：套用時間、目標位置、版本或紀錄編號，缺一不可。
  • 驗證：回到目標位置本身實查——讀回內容與交付物對照、實際行使一次功能。看交付訊息、看生產者自報、看交付包本身，都不算驗證。
  • 銷帳：在帳本或追蹤系統裡把這件事標成完成。只有套用與驗證都過了，才准銷帳；銷帳之後這件事就退出所有追蹤，所以銷帳是四步裡最不准搶快的一步。

2. 待套用清單：沒銷帳就一直釘著

  • 進榜條件：已交付、未套用，或已套用、未驗證——兩種都算未完成，都留在清單上，狀態分開標明，不准用一個「處理中」混過去。
  • 每筆必備三欄：套用目標（要進到哪個位置）、負責人（誰去套用）、期限（何時之前要套用完成）。缺任何一欄，這筆就不算被接手。
  • 出榜條件只有一個：判到 C 銷帳完成（見第 3 節）。口頭說「應該弄好了」、交付了新版本、期限到了——三種都不構成出榜理由。

3. 判定代碼與優先序

對每個情境依序檢查，取第一個成立的代碼：

  1. R 退回修訂：已經做過驗證，而且驗證結果是不通過（線上目標與交付物不一致、缺件、或功能實測失敗）→ R，當場開修訂單並給修訂期限，原筆保持未銷帳；任何銷帳提議都排在本代碼之後。
  2. B 擋下誤銷：有人提議把這件事標成完成或銷帳，但拿不出套用證據（只有交付紀錄或生產者自報）→ B，擋下不准銷，回到待套用清單釘住。
  3. E 逾時升級：已交付、未套用，而且現在已經超過任務單上的套用期限，也還沒有人升級處理 → E，把這筆往上送交負責層級，並在清單上標明逾時天數。
  4. C 銷帳完成：已套用且有完整套用證據，而且驗證已在目標位置本身實查通過（讀回對照一致、功能實測正常）→ C，銷帳，並把套用證據與驗證紀錄附在帳目上。
  5. V 待驗證：已套用且有套用證據，但驗證還沒做，或驗證已指派但尚未回報結果 → V，保持未銷帳，指派驗證並給驗證期限。
  6. P 待套用釘住：已交付、未套用、尚未超過套用期限、負責人與目標都已指名，也沒有人提議銷帳 → P，留在待套用清單上照期限追蹤，不做其他處置。

4. 證據規則

  • 套用證據只認目標位置那一側的紀錄：目標的版本紀錄、部署時間戳、線上讀回結果。生產者說「我弄上去了」不算證據。
  • 驗證只認目標位置本身：驗證者要實際打開或讀回目標位置，對照交付物逐項核對；只讀交付包就回報「驗證通過」，視同未驗證。
  • 銷帳要附鏈：帳目上必須同時附得上套用證據與驗證紀錄兩條，缺一條，這筆銷帳就不成立，事後稽核查到要退回未完成。

5. 誠實邊界

  • 本規格處理的是「有指名套用目標」的交付物：一份本來就只需要交付、沒有要進到任何線上位置的成品（例如一次性的參考報告），交付即完成，不套本規格。前提是任務單在開工時就寫明它沒有套用目標，不准事後改口。
  • 驗證的深度照風險分級：動到正式產品與對外內容的，全項對照加功能實測；低風險的文件補件，讀回對照即可。分級在任務單上先寫明，不准驗證當下自己降級。
  • 修訂不是重開新案：驗證退回的修訂沿用原筆追蹤，修好後重走套用與驗證，不另開一筆把歷史洗掉。

6. 常見錯誤清單

  • 交付即銷帳：生產者一交件就標完成，東西從沒進過目標位置，而且因為帳銷了，再也沒有清單會追它。
  • 拿自報當證據：用「他說做好了」「他說上線了」當套用或驗證依據——自報是交付的一部分，不是目標那一側的紀錄。
  • 驗證只看交付包：驗證者打開交付包看一遍就簽通過，線上目標根本沒被打開過，缺件與不一致全部漏掉。
  • 先銷帳再補驗證：想說先把帳清掉、驗證有空再補——銷帳後追蹤就停了，這個「再補」通常永遠不會發生。
  • 逾時無人管：待套用清單只是把名字列著，沒有期限與升級規則，列了跟沒列一樣，東西照樣躺到被人偶然想起。
