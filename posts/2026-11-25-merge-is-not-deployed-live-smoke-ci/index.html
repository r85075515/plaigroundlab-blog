PR 合併不等於上線：替多站靜態架構打造 0-Token 合併後活頁煙霧測試

給你的 AI：本篇另備乾淨 Markdown 的 agent 版，內含可直接跑的程式碼與驗收指令——中文版・English

一、PR 顯示 Merged，不代表使用者看得到頁面

當你同時維護 5 個以上的靜態產品站點（入口門戶、技術部落格、GPU 價格看板、小工具頁），很容易陷入「合併即結束」的錯覺：PR 過了、合併綠燈亮了，帳本就隨手關單。

直到實際用 curl 逐站掃描線上網址，才發現兩個真實發生在生產環境的斷鏈：

  • 子路徑返回 HTTP 404：私有原始碼倉庫合併了新頁面，但跨倉庫的 publish-site.yml 只設定 workflow_dispatch 與每日排程、沒有監聽 push: branches: [main]，公開 GitHub Pages 根本還沒拿到新版建置產物。
  • 新站點網域返回 HTTP 000：倉庫仍是 private 且 Pages／DNS CNAME 尚未對齊，上線網址連 TLS 握手都還沒有通。

只要沒有「對著公開 HTTPS 網址驗收 HTTP 200＋關鍵標記」的最後一關，所有 PR 合併都只是自報完工。

二、多站靜態部署常見失敗模式實測矩陣

異常模式 線上實測狀態碼 根因分析 自動防線
跨庫建置未自動觸發 HTTP 404（新路由遺失） Workflow 缺 push＋paths: ['web/**'] 觸發條件 合併進 main 自動觸發 build＋deploy
私人庫／DNS CNAME 未通 HTTP 000（連線失敗） 尚未切換公開、或 CNAME 檔遺失／DNS 未指向 公開站 CNAME 入版控＋煙霧清單必查
rsync --delete 誤清根檔 HTTP 404 / 網域失效 建置輸出資料夾漏放 CNAME 或靜態子頁 放進 public/ 自動複製並驗證
建置空頁／編譯報錯殘留 HTTP 200（假正常） 只檢查狀態碼 200，沒驗實際內容標記 同時斷言頁面含預期關鍵字串

四、核心實作程式碼（零外部依賴，可直接放進專案）

1. 零依賴多站活頁煙霧測試腳本（scripts/live_smoke.py）

#!/usr/bin/env python3
# Zero-dependency Post-Merge Live Smoke Checker for multi-site static fleets.
from dataclasses import dataclass
import sys
import time
import urllib.error
import urllib.request

@dataclass(frozen=True)
class SmokeTarget:
    name: str
    url: str
    expected_status: int = 200
    required_marker: str = ""

TARGETS = [
    SmokeTarget("Portal", "https://plaigroundlab.com/", 200, "PlAIground Lab"),
    SmokeTarget("Blog", "https://blog.plaigroundlab.com/", 200, "AI Geek Blog"),
    SmokeTarget("ComputeQuote", "https://computequote.plaigroundlab.com/", 200, "ComputeQuote"),
    SmokeTarget("Calculator", "https://computequote.plaigroundlab.com/calculator/", 200, "Payback Calculator"),
]

def probe(target: SmokeTarget, timeout: float = 12.0) -> bool:
    req = urllib.request.Request(
        target.url,
        headers={"User-Agent": "PlAIgroundLab-LiveSmoke/1.0 (+https://plaigroundlab.com)"},
    )
    t0 = time.monotonic()
    try:
        with urllib.request.urlopen(req, timeout=timeout) as resp:
            status = int(resp.getcode() or 0)
            body = resp.read().decode("utf-8", errors="replace")
            ms = round((time.monotonic() - t0) * 1000.0, 1)
            ok = (status == target.expected_status) and (target.required_marker.lower() in body.lower())
            print(f"[{'PASS' if ok else 'FAIL'}] {status} ({ms}ms) {target.name} -> {target.url}")
            return ok
    except urllib.error.HTTPError as e:
        print(f"[FAIL] {e.code} {target.name} -> {target.url}", file=sys.stderr)
        return False
    except Exception as e:
        print(f"[FAIL] 000 ({e}) {target.name} -> {target.url}", file=sys.stderr)
        return False

if __name__ == "__main__":
    results = [probe(t) for t in TARGETS]
    raise SystemExit(0 if all(results) else 1)

2. GitHub Actions 自動建置＋路徑過濾＋Deploy 後即時驗證

name: Publish Site & Verify Live
on:
  workflow_dispatch: {}
  push:
    branches: [main]
    paths:
      - "web/**"     # 僅前端異動才建置，不因 docs/scripts 更動白燒 Actions 分鐘數

jobs:
  deploy-and-verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "20"
      - run: cd web && npm ci && npm run build
      - name: Deploy & Verify Live Routes
        run: |
          sleep 30
          python3 scripts/live_smoke.py

3. Ephemeral Local Server 單元測試模式（確認 CI 不依賴外部網路也能測對）

import http.server
import threading
import unittest

class SmokeServerTest(unittest.TestCase):
    def test_catches_404_and_200(self):
        # 啟動 127.0.0.1 臨時隨機 port，獨立驗證 200+marker 通過與 404 失敗邏輯
        srv = http.server.ThreadingHTTPServer(("127.0.0.1", 0), _Handler)
        t = threading.Thread(target=srv.serve_forever, daemon=True)
        t.start()
        try:
            port = srv.server_address[1]
            self.assertTrue(probe(SmokeTarget("ok", f"http://127.0.0.1:{port}/ok", 200, "Calculator")))
            self.assertFalse(probe(SmokeTarget("404", f"http://127.0.0.1:{port}/missing", 200, "Calculator")))
        finally:
            srv.shutdown()
            srv.server_close()

五、實際踩過的 3 個部署地雷（含解法）

  1. 跨庫 PR 推不上去，原來卡在 PAT 缺少 workflow scope：自動化環境送 PR 修改 .github/workflows/*.yml 時常被遠端直接拒收。解法是在腳本裡預先準備明確 fallback：先將建議 YAML diff 檢出保留給擁有完整權限的維護者一次套用，不要讓整個靜態頁面開發分支卡死。
  2. Python 預設 User-Agent 遭邊緣 WAF 擋成 HTTP 403：瀏覽器與 curl 打同一頁都是 200 OK，只有 urllib 預設字串 Python-urllib/3.x 被安全規則擋下。自訂乾淨的識別標頭即可穩定通過檢查。
  3. 沒有加 paths: 過濾導致文件與資料異動狂觸發發布 CI：把每次資料抓價與網站建置綁在同一個 on: push 會浪費大量免費 Actions 額度。加上 paths: ['web/**'] 後，只有真正影響靜態站產物的提交才會重建上線。
