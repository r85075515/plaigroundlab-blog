# 雲端 GPU 運維判定 Runbook

用途：給定一個雲端 GPU 操作情境（開機前、開機後、運行中、收尾或失敗時），判定下一步的唯一結果代碼。本文件是完整規格：另一個 AI 只讀本文件，即可對任意情境給出唯一判定。
發布者：PlAIground Lab。適用範圍：按小時計費的雲端 GPU 機器操作；供應商與機房皆以類別指稱，不寫實際名稱。

## 0. 定義與結果代碼

- 機器（pod）：一台按小時計費的雲端 GPU 實例。同一時間最多一台在跑（見第 1 節 P2）。
- 網路磁碟（volume）：綁定特定機房的網路儲存，只放模型、資料集與輸出（見第 3 節）。
- 映像：機器啟動用的官方系統映像；映像自帶啟動腳本，負責遠端登入與初始化。
- 結果代碼（每情境只取一個，依第 5 節的階段判定）：
  - S 開機前攔下：開機前檢查任一項不過（第 1 節），不准開機，修正後重跑第 1 節。
  - H 三查暫停：機器已運行但開機三查任一項不過（第 2 節），不准丟任務，先診斷。
  - F 容量轉線：綁磁碟機房查無容量（第 4 節），改開不掛磁碟的機器並從公開來源拉模型，不乾等。
  - D 可丟任務：開機前檢查與三查全過、環境與長任務紀律齊備（第 1 至 3 節），可正式丟任務運行。
  - T 立即收尾：工作完成且產出已確認，或閒置逾 15 分鐘（第 4 節收尾規則），用終止不用停止，並完成確認與成本紀錄。
  - R 失敗停手：同一錯誤已重試 2 次仍失敗（第 4 節失敗規則），停手交紀錄，不准再換映像重試。

## 1. 開機前檢查（P，全過才准開機）

- P1 映像與啟動參數：用官方 PyTorch 映像（CUDA 12.x 系列）；啟動參數／Docker 參數必須留空。在參數欄塞任何常駐指令（例如叫機器睡著不要退出）即為 P1 不過——它會蓋掉映像自帶的啟動腳本，遠端登入與初始化不會跑。
- P2 命名與單機：本方機器用約定前綴命名；開機當下若已有另一台本方 GPU 機器在跑，P2 不過，先收尾舊機或改期。
- P3 容量先驗：開機前先對綁磁碟的目標機房查目標 GPU 容量。未查即開，P3 不過。本節只判「有沒有查」；查了且結果為無容量，走第 4 節 F，不算 P3 不過。

任一項不過，結果代碼 S：不准開機；修正後重跑本節全項，沒有「大致符合」。

## 2. 開機三查（V，機器運行後判定，全過才准丟任務）

- V1 顯示卡清單指令能列出目標 GPU。
- V2 Python 內 GPU 可用檢查回報為真。（套件版本比主機驅動新時，此項會回報假——這正是本項要抓的情況。）
- V3 磁碟空間清單正常，且目標磁碟可讀。

任一項不過，結果代碼 H：不丟任何任務，先診斷。診斷順序寫死：先查環境讀取路徑（是否有環境檔位在網路磁碟上、載入是否卡住），再查套件版本與主機驅動是否對齊。三查全過且第 3 節齊備，才可進 D。

## 3. 環境與長任務紀律（E／L，丟任務前須齊備）

- E1 用系統 Python，套件裝在容器本機磁碟；絕不在網路磁碟上建虛擬環境。情境若明文要在網路磁碟建虛擬環境，屬 E1 違反：在開機前階段記 S、在已運行階段記 H（先遷移環境再談任務）。
- E2 網路磁碟只放模型、資料集、輸出。
- L1 長任務以背景常駐方式運行，紀錄寫檔並以 tail 輪詢；不讓連線中斷能殺掉任務。
- L2 每 250 步存檢查點，附雜湊值存入磁碟或程式庫。

第 1、2 節全過、但 E／L 任一未齊備者，尚未達 D：補齊後才丟任務（此情形不另設代碼，判定時記為「未達 D，缺 E／L」並指出缺項；練習情境若未提及 E／L，視為齊備）。

## 4. 轉線、收尾與失敗（三條生命週期規則）

- F 容量轉線：已照 P3 查過容量、結果為綁磁碟機房無目標 GPU 時，結果代碼 F：改開不掛磁碟的機器，模型與資料從公開來源重新拉取，產出上傳確認後照收尾規則刪機。此情形不准乾等，也不記 S——P3 判的是有沒有查，不是查到的結果。
- T 收尾：滿足下列任一觸發——（i）工作完成且產出已確認存好；（ii）機器閒置逾 15 分鐘。結果代碼 T，動作四步缺一不可：用終止（terminate）刪除機器（用停止 stop 代替即違反本條，停止狀態仍收儲存費）、列機器清單確認已刪除、把本台成本記進版本紀錄、（觸發為（i）時）產出確認在終止之前完成。工作未完成且產出未確認時，不觸發 T，先完成或先存好產出。
- R 失敗上限：同一個錯誤已重試 2 次仍失敗時，結果代碼 R：停手，把完整紀錄交回決策端。此情形不准換映像再試——換映像不重置重試計數，同錯第 3 次嘗試一律禁止。

## 5. 判定順序（依情境所述階段判定）

每個情境只問其明文所述的生命週期階段，依下列順序取第一個成立的代碼；情境未提及的條件視為符合規定，明文寫出的事實照明文判定：

1. 情境在開機前階段：第 1 節任一項不過 → S；全過且容量查有 → 進開機（本階段無代碼，逕判下一步）；容量查過且無 → F（第 4 節先於開機）。
2. 情境在開機後、丟任務前：三查任一不過 → H；全過且 E／L 齊備 → D。
3. 情境在運行或收尾階段：先判 R（同錯已重試 2 次仍失敗 → R），再判 T（觸發條件成立 → T）；兩者皆不成立且任務進行中 → 繼續運行（無代碼）。
4. 跨階段衝突時，階段以情境明文為準：例如收尾情境即使開機前與三查曾全過，也只判 T／R，不回頭重判 S／H／D。

## 6. 判定練習（自測用）

對下列每一情境，依第 0 至 5 節給出：結果代碼（S／H／F／D／T／R，或「未達 D」）與關鍵理由。答案在第 7 節，先做完再對照。本節未特別註明的條件，視為符合規定；情境明文寫出的事實，照明文判定。各情境只問其所屬階段。

- C1：一台機器準備開機：官方 PyTorch 映像、啟動參數留空、用約定前綴命名、當下無其他本方 GPU 機器在跑、已先查綁磁碟機房容量且查有。開機後三查全過，環境用系統 Python 且套件在本機磁碟，長任務將以背景常駐加紀錄寫檔運行、每 250 步存檢查點。問：現在能否丟任務？
- C2：一台機器準備開機，其餘條件全合規，但操作者在啟動參數欄填了常駐指令，要求機器啟動後睡著不要退出。問：能否照此開機？
- C3：一台機器已開機運行，顯示卡清單列得出目標 GPU、磁碟清單正常，但 Python 內 GPU 可用檢查回報為假。問：能否丟任務？
- C4：綁磁碟機房的目標 GPU，操作者已照規格先查容量，結果為無容量；模型與資料都能從公開來源重新拉取。操作者提議在原機房乾等到有貨為止。問：正確處置？
- C5：一台機器上的工作已全部完成，產出已確認存好。操作者打算用「停止」代替「終止」，把機器留著明天再用。問：正確處置？
- C6：一台機器運行中，某一步驟以同一個錯誤連續失敗，操作者已照原配置重試 2 次仍失敗。操作者提議換一個非官方映像再試第 3 次。問：正確處置？

## 7. 參考答案

- C1 → D 可丟任務。P1 至 P3 全過（官方映像、參數留空、前綴命名、單機、容量先查且查有）；V1 至 V3 全過；E／L 齊備（系統 Python 本機裝、背景常駐加紀錄寫檔、250 步檢查點）。照第 5 節第 2 段，全過即 D。
- C2 → S 開機前攔下。P1 不過：啟動參數填入常駐指令會蓋掉映像自帶啟動腳本，遠端登入與初始化不會跑。清空參數後重跑第 1 節，才可開機；其餘條件合規不改變本項判定，身分與順序上開機前檢查先於一切。
- C3 → H 三查暫停。V2 不過（GPU 可用回報為假），即使 V1、V3 皆過，三查須全過才准丟任務。照第 2 節先診斷（先查環境讀取路徑，再查版本與驅動對齊），不丟任務。
- C4 → F 容量轉線。P3 已滿足（判的是有沒有查，本情境查了）；查無容量且模型可從公開來源拉取，照第 4 節改開不掛磁碟的機器，不乾等、不記 S。
- C5 → T 立即收尾。觸發（i）成立（工作完成、產出已確認）；收尾必須用終止而非停止（停止仍收儲存費），並列清單確認刪除、記成本。「留著明天再用」不成立。
- C6 → R 失敗停手。同錯已重試 2 次仍失敗，已達上限；換映像不重置計數，第 3 次嘗試禁止。停手並把完整紀錄交回決策端。
