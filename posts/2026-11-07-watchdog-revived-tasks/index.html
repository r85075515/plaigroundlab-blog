看門狗差點把做完的任務「復活」：狀態機衛生學

給你的 AI：本篇另備乾淨 Markdown 的 agent 版，讀了就能照著做——中文版・English

前段：寫給人看的故事

我們有一支 AI 工人艦隊，任務用檔案管理：待辦放在 pending/、被認領的放在 claimed/、做完的結果放在 done/。為了防止「任務被認領後工人死掉、單子永遠卡住」，我們養了一隻看門狗：定時掃描 claimed/，凡是認領時間超過門檻、遲遲沒下文的，就搬回 pending/ 讓別人接手。

聽起來很單純。然後它兩天內差點出兩次大事，而且兩次都是靠運氣才沒出事。

第一次（2026-10-22）。 看門狗照著規則算：claimed/ 裡有 52 件「認領很久了」，全部該搬回待辦。幸好搬回的寫入全部被伺服器拒絕（HTTP 422）——因為 pending/ 裡已經躺著同名的歸檔存根，新檔撞名寫不進去。事後我們把那 52 件逐一打開看，全部都是早就做完的任務：工人完成後會把結果寫進 done/，但 claimed/ 裡會留下一份殘留副本，檔頭明明寫著「已完成並歸檔」、還附完成時間跟 PASS 判定。看門狗只看「認領時間」，從不打開檔案看內容。如果那天 422 沒擋住，52 件已完成的任務會被「復活」重跑一遍，完成紀錄還會被覆蓋掉。

第二次（2026-10-23）。 我們已經修了第一課：搬回前先讀檔案內容，看到完成標記的就跳過。結果隔天看門狗又挑出 13 件要搬回——這次是舊格式的殘留副本：工人做完後根本沒更新 claimed/ 裡的那份，沒有完成標記、沒有完成時間，格式檢查完全通過。但它們全都在 done/ 裡有結果，是做完的任務。這次救命的是 API 速率限制（HTTP 403），搬回根本沒執行成功。兩次都不是我們的設計救了自己，是別人的錯誤訊息救了我們。

同場加映一個小地雷：工人的認領時間字串帶著地區後綴（像 （鳳凰城）），標準的時間解析器直接炸掉、回傳空值，看門狗差點把一批正常的單誤判成「無法解析的殭屍」。先把尾巴的括號後綴剝掉再解析，才解決。

最後定版的規則只有一句話：格式檢查是必要條件，done/ 裡有沒有結果才是充分條件——兩個都過，才准搬。 搬回前先用全樹索引把 done/ 的任務編號建好，編號在裡面的，一律視為殘留跳過。加上搬回前先出乾跑清單、逐件記錄搬移理由，看門狗從此沒再誤傷。

這篇文章的後段，是這套「安全回收器」的完整規格：掃描、時間解析、雙閘檢查、乾跑清單、執行與稽核——可以直接搬去給任何「用檔案或佇列管理任務」的系統用。

以下為完整 runbook

1. 問題模型

檔案式任務系統有三個狀態目錄：pending/（待辦）、claimed/（已認領）、done/（完成結果）。回收器的職責是把「認領後失聯」的任務搬回 pending/。危險在於：claimed/ 裡的檔案不是認領狀態的可靠證據——完成流程會留下殘留副本，且殘留格式不只一種。用單一訊號（認領時間）做破壞性搬移，遲早誤傷已完成任務。

2. 回收判定：三道閘，依序全過才搬

  1. 時間閘：claimed_at 解析成功，且距今超過卡單門檻（本系統用 48 小時）。
  2. 內容閘：讀檔案全文——出現完成標記（完成檔頭、或 done_at 欄位、或完成判定欄位）任一者，跳過，理由記 residual-with-marker。
  3. 結果閘：建 done/ 全量索引（任務編號集合，來源用版本庫的 tree 清單一次取齊，不要逐檔探測）。編號在索引中，跳過，理由記 residual-with-result。

只有三閘全過（夠舊、無完成標記、done/ 無結果）的，才是真的卡單。

3. 時間解析的衛生

  • 時間字串先做正規化：剝除結尾的括號註記（全形／半形括號都算，例如地區名後綴），再交給 ISO 解析器。
  • 解析失敗不等於卡單：歸入 unparseable 類，只通報、不搬移。把解析失敗當成「很舊」是誤傷的捷徑。

4. 執行紀律

  • 先乾跑：先產出候選清單（編號、認領時間、三閘各自結果、預定動作），人或上層系統看過才執行；自動執行也要把乾跑清單留檔。
  • 逐件記錄：每個搬移記一行：編號、原路徑、新路徑、三閘結果、時間。跳過的也要記理由。
  • 不覆蓋：目標目錄已有同名檔案時停下來通報，不強行寫入。（本案第一次事故正是被「撞名拒寫」救下的——但那是運氣，正規做法是自己先檢查。）
  • 限量：單輪搬移設上限（例如 20 件）；候選異常多（例如超過平時 5 倍）先通報再執行——大量「卡單」同時出現，通常是判定壞了，不是工人全死。

5. 驗收清單

給一组 fixture 目錄，四種檔案各一：

  1. 已完成、新格式殘留（有完成標記）→ 必須跳過。
  2. 已完成、舊格式殘留（無標記，但 done/ 有同編號結果）→ 必須跳過。
  3. 真卡單（夠舊、無標記、done/ 無結果）→ 必須搬回。
  4. 新認領（未超門檻）→ 必須不動；時間字串帶地區後綴的正常單 → 必須正確解析、不誤判。

四種行為全對，回收器才算合格。

6. 通用教訓

  • 破壞性自動化要查地面真相：要刪、要搬、要覆蓋之前，去問「結果存放區」而不是「狀態自報區」。
  • 被錯誤訊息救兩次，是設計在跟你求救：422 與 403 都是別人的煞車；自己的煞車要自己裝。
  • 必要條件與充分條件分開寫：格式像不像完成（必要）與結果存不存在（充分）是兩種證據，用途不同，不可互相冒充。
