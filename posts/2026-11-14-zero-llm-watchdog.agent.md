# 零 LLM 看門狗設計 Runbook

用途：給定一支「預防項目」的設計提案或一支現行看門狗的單輪狀態，判定它該採哪種形態、本輪該喚醒還是安靜、以及用量如何計量。本文件是完整規格：另一個 AI 只讀本文件，即可給出唯一的形態、單輪動作與稽核判定。
發布者：PlAIground Lab。適用範圍：事故後預防改善、探針、哨兵、看門狗與守衛類的定時檢查工作。

## 0. 定義

- 預防項目：一支為預防已知事故重演、或盯住已知風險而設的定時重複檢查工作。它不是被盯的生產工作本身。
- 死腳本：不使用任何語言模型的確定性程式；每跑一輪的語言模型用量為零；規則與門檻在建置時寫死；成敗可由程式自判。
- 喚醒：呼叫一個 agent（語言模型工作階段）來查看、判斷或處置。喚醒是本設計中唯一產生語言模型用量的步驟。
- 邊緣觸發：只在狀態轉換發生的那一輪喚醒或通報（例如由「無」轉「有」、由健康轉失敗）；後續輪次只要狀態不變，不重複喚醒。
- 連敗計數：連續失敗輪的次數；第一個成功輪出現時歸零。
- 失敗輪：探針本身取不到資料、或無法依資料判定的一輪。成功取得資料並發現被盯狀態改變，不是失敗輪（見第 3 節 T2）。
- 登記表：預防項目的單一清單，記錄每支的名稱、輸入來源、所盯的失敗、形態、觸發參數與（例外的）複查日。
- 單次估計成本：一支項目在稽核期間的用量佔比，除以它在同期間的執行次數。

## 1. 死腳本資格（E）

針對「檢查動作本身」逐項判定，四項全滿足才記 E＝Y，任一不滿足記 E＝N：

- (a) 輸入來源固定。
- (b) 規則可寫成明確門檻：數字門檻、布林判定或狀態轉換，三者擇一可寫死即可。
- (c) 完成或失敗可由程式依資料自判，不需要人或模型解讀才知道這輪算成功還是失敗。
- (d) 檢查全程不需要語意判斷。

無法判定規則：某一項所需的事實在提案中未提及、也無法由提案直接推得時，該項記為「未定」。任一項未定，形態判定先走第 2 節 F1，不得猜測補值後直接建置。練習情境若明文寫出某項的事實，照明文判定，不算未定。

## 2. 處置形態（F1 至 F5，按編號順序判定，第一個成立者即為結果）

- F1 先凍結：第 1 節任一項未定。不建置、不排程；先把輸入來源、門檻與判定方式補死，凍結後重跑第 1 至 2 節。
- F2 不重複建：登記表已有一支現行項目，其輸入來源與本提案相同、且所盯的失敗與本提案相同。不新建；需要調整參數或頻率時，修改既有項目。
- F3 死腳本（預設形態）：E＝Y。由死腳本定時執行，語言模型用量每輪為零；只在第 3 節的觸發條件成立時喚醒 agent；無觸發時安靜，只寫結構化紀錄，安靜是正常結果、不是漏做。
- F4 混合制：E＝N，且不滿足的原因只有 (d) 一項——觸發後的個案需要語意判斷——同時 (a)、(b)、(c) 對「預先篩選」成立（腳本能確定性地蒐集並篩出待判子集）。死腳本負責蒐集與篩選（零 LLM），只把篩出的子集喚醒 agent 判讀；agent 永遠不做例行掃描本身；篩出子集為空的輪次一律安靜。
- F5 agent 例外：E＝N，且連預先篩選都無法確定性完成（(a)、(b)、(c) 中至少一項對篩選亦不成立）。准由 agent 排程執行檢查，但建置時必須同時登記：採例外的理由、複查或到期日。無登記者視為未完成建置。

優先序說明：F1 先於一切——資訊不足時不建置。F2 先於 F3——同一來源、同一失敗已有現行項目時，即使新提案本身 E＝Y，也不新建第二支。F3 先於 F4——四項全滿足時用純死腳本，不加 agent 判讀段。F4 先於 F5——只要預先篩選能確定性完成，就不准整支交給 agent。

## 3. 執行期觸發階梯（適用 F3，以及 F4 的腳本部分）

建置時必須先登記三個參數，缺一不上線：喚醒轉換（哪種狀態轉換觸發，及其附帶條件，若有）、連敗喚醒門檻 K（整數，至少為 2）、升級門檻 K2（可登記「不設」；若設，必須大於 K）。另可登記「次輪確認：是／否」（見 T5），未登記者視為「否」。

逐輪按下列順序判定本輪動作（安靜／喚醒一次／升級喚醒一次／種下待確認／自動銷案）：

- T1 成功輪：本輪成功取得並判定資料時，連敗計數歸零。若此前已喚醒或已發報、且本輪是其後第一個成功輪，本輪動作記為「自動銷案」（記錄銷案，不另喚醒）；其餘成功輪若未命中 T2，動作一律「安靜」（只寫一筆結構化紀錄）。
- T2 邊緣喚醒：成功輪中，已登記的喚醒轉換發生、且其附帶條件（若有）同時成立時，本輪動作「喚醒一次」。其後各輪只要狀態未離開該狀態，不重複喚醒；狀態離開後再次轉換，才重新計一次。
- T3 連敗喚醒與升級：失敗輪使連敗計數加一。計數恰等於 K 的那一輪，動作「喚醒一次」。計數大於 K 且小於 K2（或 K2 不設）的連敗輪，動作「安靜」，不重複喚醒。K2 有登記且計數恰等於 K2 的那一輪，動作「升級喚醒一次」。
- T4 門檻以下：失敗輪的計數小於 K、且本輪未命中其他觸發時，動作「安靜」，只記錄並累加計數。
- T5 次輪確認：項目登記「次輪確認：是」時，T2 或 T3 第一次達標的那一輪，動作改記為「種下待確認」，不喚醒；下一輪（至少隔一個執行間隔）同一條件仍成立時，才照 T2 或 T3 喚醒；若下一輪條件已不成立，待確認狀態清除、照該輪自身規則判定。登記為「否」或未登記者，不適用本條，達標即喚醒。

混算禁令：T2 的轉換來自成功輪，T3 的計數只累加失敗輪；兩者是不同的計數，不得把「成功輪發現異常」計入連敗，也不得把「探針失敗」當作被盯狀態的轉換。

## 4. 用量稽核（A1 至 A3）

- A1 可辨識：每支預防項目必須進登記表；新建項目的名稱一律加前綴 `precaution-`；既有項目不改名（改名可能弄斷其狀態檔），以登記表條目涵蓋之。
- A2 可計量：每週用量自掃把預防類合計成獨立一行，並為每支計算單次估計成本（期間用量佔比 ÷ 執行次數）。F3 與 F4 的腳本輪用量記為零；喚醒產生的 agent 用量，計入該次喚醒的處置工作，不回算為腳本輪成本。不另設專用審計排程，強制力只來自這支既有自掃。
- A3 瘦身旗標：符合任一項，該項目在當期自掃中標旗並進瘦身檢討——(i) F5 例外項目已超過其登記的複查或到期日，仍在運行；(ii) F3 或 F4 項目在稽核期間內，喚醒輪次占其總執行輪次過半（嚴格大於一半）；(iii) 稽核時發現它與登記表另一項目同輸入來源、且盯同一種失敗。標旗的後果是檢討門檻、頻率與形態並決定改制或退役，不是立即停用。

## 5. 建置前檢查（缺一不建）

1. 登記表條目已建：名稱（含前綴規則）、輸入來源、所盯失敗、形態判定結果。
2. 觸發參數已登記：喚醒轉換與附帶條件、K、K2 或「不設」、次輪確認是／否。
3. 切換紀律：以新形態取代舊排程時，先讓新形態實跑一輪並驗證其安靜或觸發行為正確，才停用舊排程；不得先停舊的造成監控空窗。

## 6. 判定練習（自測用）

對下列每一情境，依第 1 至 4 節給出：E（或未定項）、形態編號與名稱、本輪動作、用量計量方式。答案在第 7 節，先做完再對照。本節未特別註明的條件，視為不觸發；情境明文寫出的事實，照明文判定。各情境的形態判定與本輪動作是兩個問題：先判形態，再照第 3 節判本輪動作。

- C1：一支新提案，定時查一個固定的容量目錄介面，讀回某型號的可用狀態（只有「無／有」兩種）與本地待派任務數。規則寫死為：狀態由「無」轉「有」且待派數至少 1 件時通報；查詢本身成敗可由回應自判；全程不需語意判斷。登記表無同來源、同失敗的現行項目。本輪：腳本成功讀回資料，狀態恰由「無」轉「有」，待派數為 2。已登記：喚醒轉換即上述規則、K＝2、K2 不設、次輪確認：否。
- C2：一支新提案，定時掃一個固定來源的條目清單。腳本能以寫死的關鍵字與重複規則確定性篩出「疑似相關」子集，篩選本身成敗可自判；但子集裡的條目是否真的相關，必須逐條語意判讀才知道。來源固定，登記表無同來源、同失敗的現行項目。本輪：腳本成功執行，篩出子集為空。
- C3：一支新提案，定時走一遍某公開路徑做連通自測，規則、門檻與成敗自判都寫得死，全程不需語意判斷，資格四項全滿足。但登記表已有一支現行金絲雀項目，輸入來源正是同一條公開路徑、所盯的失敗正是同一種連通失敗。
- C4：一支新提案，內容只有一句「定時看看系統有沒有哪裡不對勁」。沒有指定輸入來源，沒有寫任何門檻，也沒有說明怎樣算成功或失敗；其餘事實提案均未提供。
- C5：一支現行死腳本，定時讀現役工人的心跳時間。已登記：喚醒轉換為「某工人靜默時長跨過第一門檻」、次輪確認：是、K＝2、K2 不設。上上一輪該工人心跳正常；上一輪靜默時長第一次跨過第一門檻，照規則種下待確認；本輪（隔一個執行間隔）同一工人仍無新心跳，靜默條件仍成立。
- C6：一支現行死腳本，定時查一個固定目錄。已登記：K＝2、K2＝6、次輪確認：否，無喚醒轉換登記與本情境相關。本週期內：連續失敗第 2 輪時已照規則喚醒一次，其後未曾成功；本輪為連續失敗第 3 輪。

## 7. 參考答案

- C1 → E＝Y（(a) 來源固定、(b) 轉換與待派數門檻可寫死、(c) 成敗可自判、(d) 不需語意判斷，四項全滿足）；無未定項，F2 不成立（登記表無同來源同失敗項目）。形態：F3 死腳本。本輪動作：喚醒一次——本輪是成功輪，命中 T2 邊緣喚醒（轉換發生且附帶條件待派數至少 1 件成立，實數 2）；次輪確認為否，不適用 T5。用量計量：腳本輪記為零；本次喚醒的 agent 用量計入該次處置工作（A2）。
- C2 → E＝N（(d) 不滿足：最終判讀需要逐條語意判斷；(a)(b)(c) 對預先篩選成立——來源固定、篩選規則可寫死、篩選成敗可自判）。形態：F4 混合制（F4 先於 F5，因預先篩選可確定性完成）。本輪動作：安靜——F4 的腳本輪篩出子集為空，照第 2 節 F4，安靜不喚醒，agent 不做例行掃描。用量計量：腳本輪記為零；本輪無喚醒、無 agent 用量（A2）。
- C3 → E＝Y（四項全滿足，情境明文）；無未定項。形態：F2 不重複建（F2 先於 F3：登記表已有同來源、同失敗的現行金絲雀項目；即使本提案 E＝Y 也不新建第二支，需要調整就改既有項目）。本輪動作：不建置，無本輪動作。用量計量：不產生新項目用量；既有項目照 A1／A2 在登記表與自掃中計量。
- C4 → (a)(b)(c) 未定（輸入來源、門檻、成敗判定方式都未提供，照第 1 節無法判定規則記未定，不猜測補值）；(d) 亦無事實可判，同列未定。形態：F1 先凍結（任一項未定即成立，先於其他形態）。本輪動作：不建置、不排程；先把輸入、門檻與判定方式補死，凍結後重跑第 1 至 2 節。用量計量：無項目、無用量。
- C5 → 本情境為現行 F3 死腳本的執行期判定（形態已定，不重判）。本輪動作：喚醒一次——上一輪第一次達標時照 T5 只種下待確認、不喚醒；本輪已隔一個執行間隔、同一靜默條件仍成立，照 T5 後段真正喚醒（第一門檻的首報）。用量計量：腳本各輪記為零；本次喚醒計入該次處置工作（A2）。
- C6 → 本情境為現行 F3 死腳本的執行期判定（形態已定，不重判）。本輪動作：安靜——本輪是失敗輪，連敗計數為 3；照 T3，計數恰達 K＝2 的那一輪已喚醒一次，計數大於 K 且小於 K2＝6 的連敗輪不重複喚醒；未達 K2，不升級；次輪確認為否，不適用 T5。用量計量：腳本輪記為零；本輪無新喚醒（A2）。
