例行寫入走固定入口：消滅審批卡轟炸

給你的 AI：本篇另備乾淨 Markdown 的 agent 版，讀了就能照著做——中文版・English

前段：寫給人看的故事

審批機制的本意是讓人在關鍵動作前看一眼，但它有一個隱藏的計費單位：每一個不同的指令字串，都是一張新的審批卡。例行寫入如果每次都即興拼一條新指令——換個檔名、換個參數、換個工具——在系統眼裡就每次都是「第一次見到的動作」，人就得一次又一次按允許。

我們吃過這個虧。一次交付六個多檔案，逐檔產生下載連結，每一檔的指令字串都不同，結果一個小時內跳出六張以上的審批卡，當場被抗議：能不能不要再這樣轟炸？檔案沒有做錯任何事，錯的是執行形態——同一類例行動作，被拆成了一堆長得互不相同的指令。

修法不是叫人按快一點，也不是關掉審批，而是把例行動作收斂成一個固定入口：一支登記在案的腳本，指令字串永遠同一條；所有變化——要寫哪個 repo、哪個路徑、內容來自哪個檔案——全部寫進一份獨立的作業規格檔，不進指令列。指令列不變，審批一次涵蓋長期；規格檔是資料，不是新指令。

固定入口還順手解決了第二個問題：安全護欄可以集中裝在一處。入口在真正寫入之前，先把整批規格的內容全部載入，逐項跟遠端現行版本比對：新內容若刪掉了遠端有的任何標題，或行數縮水超過兩成且超過十行，整批直接攔下、零寫入——這種「寫入時把別人的段落整段抹掉」的事故，我們也吃過。護欄只在入口裝一次，所有例行寫入就自動受保護，不靠每次執行的人記得檢查。

第三條紀律是憑證的位置：規格檔裡只准有操作清單，不准出現任何金鑰或憑證值；憑證走既有的保管機制，由入口在送出請求時掛上，不經過規格、不經過指令列、更不貼進任何對話。

當然，固定入口不是萬能通行證。第一次出現的新目標、新權限、要寫進規格的秘密——這些不是「例行」，不在一次審批的涵蓋範圍內，照舊升級給決策者。這篇的後段把界線寫死：什麼叫例行、四種判定代碼的優先序、整批預檢的原子性，讓任何人——或任何 AI——拿到一個寫入情境，都能給出唯一判定。

以下為完整 runbook

1. 固定入口的形狀（F）

  • F1 單一腳本：所有例行外部寫入（程式庫檔案的新增、更新、刪除）只經一支登記在案的腳本執行，指令字串逐字固定、永不變動。
  • F2 規格外置：每次要寫什麼，寫在一份獨立的作業規格檔裡——每筆操作列明操作別（put／delete）、目標 repo、路徑、內容來源（本機檔案或文字）與可選的提交訊息；指令列不帶任何檔名或數值。
  • F3 一批一跑：一批多筆操作寫在同一份規格、跑同一次入口、最多一張審批卡；背景跑完為止。
  • F4 清檔時機：規格檔只在整批全部成功後才清空；中途失敗，規格保留供診斷與重跑。
  • F5 檔案交付同理：要交付多個檔案，用附件或打包成一個壓縮檔一次送出，不逐檔產生連結——逐檔連結與逐檔指令是同一種轟炸。

2. 例行的定義（R，全數成立才算例行）

  • R1 類型既有：操作類型與過去做過的同型（例行程式庫寫入、例行檔案交付），不是第一次出現的新動作類別。
  • R2 目標在冊：目標 repo 與路徑在例行清單（allowlist）之內。
  • R3 規格無密：規格檔與指令列都不含任何金鑰、密碼或憑證值；憑證由入口經既有保管機制掛上。
  • R4 不擴權：不需新帳號、新工具安裝、新權限或新的對外關係。

3. 整批預檢護欄（G，寫入前全批先檢）

  • G1 預檢先行：入口在寫入任何一筆之前，先載入整批內容、逐筆抓遠端現行版本比對；任一筆觸發護欄，整批中止、零寫入。
  • G2 標題護欄：新內容刪掉遠端版本擁有的任何一個 Markdown 標題，即觸發。
  • G3 縮水護欄：新內容比遠端少超過 20% 且少超過 10 行，即觸發。
  • G4 豁免：只有決策者明示的覆寫許可（記錄在規格裡）能解除 G2／G3；豁免只解除護欄，不解除第 2 節的例行界線——不在冊的目標，有豁免也照樣升級。

4. 四種判定（代碼與優先序）

對任一寫入情境，依下列優先序取第一個成立的代碼，每個情境只取一個：

  1. E 升級決定：情境違反 R2、R3 或 R4 任一項——目標不在冊、規格或指令含秘密、或需要擴權／新帳號／新工具。不執行，交決策者。
  2. R 改走固定入口（Reroute）：內容本身例行（R1 至 R4 全過），但提議的執行形態不是固定入口——即興新指令字串、逐筆逐檔拆開跑、換一個未登記的工具。不照提議執行；改寫成一份規格、走固定入口重跑。
  3. G 護欄攔下：走固定入口，但預檢觸發 G2 或 G3，且規格裡沒有決策者的明示豁免。整批零寫入，修正規格或取得豁免後重跑。
  4. P 放行執行：R1 至 R4 全過、走固定入口、預檢通過（或觸發護欄但已有明示豁免）。照規格整批執行，全部成功後清規格檔。

5. 常見錯誤清單

  • 逐檔跑上傳、逐筆拼新指令：每條字串都是一張新卡，一小時六張卡就是這樣來的。
  • 把檔名與數值拼進指令列：字串一變，長期審批的涵蓋就失效，下一批又從第一張卡開始。
  • 護欄逐筆邊寫邊檢：寫到第三筆才發現第一筆有問題，前兩筆已經出去了；預檢必須整批先行、零寫入中止。
  • 把金鑰寫進規格圖方便：規格是會被讀、被存、被轉交的資料檔，秘密一進去就等於擴散。
  • 拿「上次有豁免」放行不在冊的新目標：豁免只解護欄，不擴例行範圍。
