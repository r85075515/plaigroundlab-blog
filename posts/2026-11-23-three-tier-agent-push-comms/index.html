從 20 秒輪詢到 73.8 ms 喚醒：用 $0 Cloudflare Workers＋Tunnel 打造三層容錯通訊網

給你的 AI：本篇另備乾淨 Markdown 的 agent 版，內含可直接跑的程式碼與驗收指令——中文版・English

一、為什麼 20 秒輪詢撐不住多 AI 協作？

當一個團隊裡有多位常駐雲端 VM 與本機開發機的 AI 代理人協同開發時，早期最容易寫出來的互通方式是「每 20 秒打一次 GitHub Issue Comments API」。跑幾天就會發現三個硬傷：

  • 節奏破碎：雙方一來一往動輒多等 40–60 秒，在需要即時審查 PR、安全確認、測試驗收時體感像慢動作。
  • 無效耗損與睡眠掉單：筆電休眠或暫斷網期間不會自己重放；若忘記設 If-None-Match，閒置期一樣消耗 API 配額。
  • 單模型配額一滿就卡住：背景無頭排程如果綁死單一模型，一旦該配額池見底，整個管線就停擺等 5 小時重置。

最後我們定下一個嚴格條件：不加任何雲端付費主機（維持 $0/月），把本機接收端改造成 73.8 ms 即時 Push ＋ 三層自動自癒 ＋ 跨三配額池自動降級 的常駐匯流排。

二、改版前後實測數據對比

評估指標 舊架構（20s GitHub API 輪詢） v2.0（三層容錯 Push 匯流排） 實測效果

四、核心程式碼與設定檔（已全面脫敏，可直接取用）

1. Cloudflare Worker Inline Push：8 秒逾時＋2xx 不堆積 KV

// mailbox-worker.js（Cloudflare Workers + KV 核心轉發邏輯）
const PUSH_TIMEOUT_MS = 8000;

async function deliverOrQueue(env, mailbox, id, msg) {
  const pushUrl = env[`${mailbox.toUpperCase()}_PUSH_URL`];
  const pushKey = env[`${mailbox.toUpperCase()}_PUSH_KEY`];
  if (!pushUrl || !pushKey) {
    await env.MAILBOX.put(`msg:${mailbox}:${id}`, JSON.stringify(msg), { expirationTtl: 86400 });
    return { result: 'queued_kv', status: null };
  }

  try {
    const res = await fetch(pushUrl, {
      method: 'POST',
      redirect: 'manual',
      signal: AbortSignal.timeout(PUSH_TIMEOUT_MS),
      headers: {
        'content-type': 'application/json',
        'authorization': `Bearer ${pushKey}`,
        'x-fleet-mailbox-id': id,
      },
      body: JSON.stringify(msg),
    });
    if (res.ok) {
      return { result: 'delivered', status: res.status };
    }
  } catch (_) {}

  await env.MAILBOX.put(`msg:${mailbox}:${id}`, JSON.stringify(msg), { expirationTtl: 86400 });
  return { result: 'queued_fallback', status: 502 };
}

2. 本機零外部套件接收器：常數時間驗簽＋原子信號檔

接收器刻意不依賴 FastAPI／Flask 等第三方框架，純用 Python 3 標準函式庫綁定 127.0.0.1:18792，降低供應鏈風險並確保冷啟動毫秒級完成：

# push_receiver.py（Python 3 stdlib only）
import hmac
import json
import os
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
from pathlib import Path

STATE_DIR = Path(os.path.expanduser("~/.agent-receiver/state"))
PUSH_KEY = Path(os.path.expanduser("~/.secrets/push_key")).read_text(encoding="utf-8").strip()
SEEN_IDS = set()

class Handler(BaseHTTPRequestHandler):
    def do_POST(self):
        if self.path != "/push":
            return self._json(404, {"ok": False, "error": "not_found"})
        auth = (self.headers.get("Authorization") or "").split(None, 1)
        if len(auth) != 2 or auth[0].lower() != "bearer" or not hmac.compare_digest(auth[1], PUSH_KEY):
            return self._json(401, {"ok": False, "error": "unauthorized"})

        length = int(self.headers.get("Content-Length", "0"))
        if length <= 0 or length > 16384:
            return self._json(400, {"ok": False, "error": "invalid_payload_size"})

        payload = json.loads(self.rfile.read(length).decode("utf-8"))
        msg_id = (self.headers.get("x-fleet-mailbox-id") or payload.get("id") or "").strip()
        if msg_id and msg_id in SEEN_IDS:
            return self._json(200, {"ok": True, "duplicate": True, "id": msg_id})

        STATE_DIR.mkdir(parents=True, exist_ok=True)
        tmp = STATE_DIR / "wake.signal.tmp"
        tmp.write_text(json.dumps(payload, ensure_ascii=False) + "\n", encoding="utf-8")
        os.replace(tmp, STATE_DIR / "wake.signal")  # 原子替換，避免讀到寫到一半的 JSON
        if msg_id:
            SEEN_IDS.add(msg_id)
        return self._json(200, {"ok": True, "duplicate": False, "id": msg_id})

    def _json(self, status: int, obj: dict):
        raw = json.dumps(obj).encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(raw)))
        self.end_headers()
        self.wfile.write(raw)

ThreadingHTTPServer(("127.0.0.1", 18792), Handler).serve_forever()

五、實際踩過的 3 個地雷（附真實錯誤訊息與解法）

  1. cloudflared tunnel route dns 悄悄綁進舊 Tunnel：在同一台已有預設 ~/.cloudflared/config.yml 的機器直接跑 cloudflared tunnel route dns <new-name> <host>，日誌竟印出舊的 tunnelID。解法是強制帶上 --config ~/.cloudflared/agent-hook.yml route dns --overwrite-dns <NEW_UUID> <host>，永遠顯式指定新 UUID。
  2. Python urllib 預設 UA 吃到 Cloudflare HTTP 403：剛建置完成時，Cloudflare Workers 與本機 curl 打健康檢查都穩拿 HTTP 200，但 Python urllib.request.urlopen 卻回 <HTTPError 403: 'Forbidden'>。最後將後端探針全面統一改用帶明確 User-Agent 的 curl。
  3. 背景守護程序 GIT_EDITOR=false 擋死 git rebase --continue：背景自動解狀態檔衝突時，即使指令傳了 -c core.editor=true，仍失敗於 error: there was a problem with the editor 'false'，因為環境變數 GIT_EDITOR 優先權高於 git config。在封裝子行程環境強制注入 env["GIT_EDITOR"] = "true"，並用臨時 bare 倉庫跑真實 rebase 衝突測試後徹底根治。
