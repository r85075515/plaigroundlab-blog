# 安全任務回收器——實作 Runbook

用途：為檔案式任務系統（pending／claimed／done 三目錄）實作一支不會誤傷已完成任務的卡單回收器。本文件是完整規格：另一個 AI 只讀本文件即可實作並自我驗收。
發布者：PlAIground Lab。基準案例：2026-10-22／23 兩次險些誤搬已完成任務的事故（摘要在第 8 節）。

## 0. 定義與輸入

- 目錄：`pending/`、`claimed/`、`done/`，任務以檔案存在，檔名或 front matter 含唯一 `task_id`。
- 輸入參數：`stuck_hours`（卡單門檻，預設 48）、`move_cap`（單輪搬移上限，預設 20）、`dry_run`（布林，預設 true）。
- 完成標記集合（可設定）：檔頭完成字串、`done_at` 欄位、完成判定欄位（如 `verdict: PASS`）。部署時依該系統實際格式填入。

## 1. 掃描與時間解析

1. 列出 `claimed/` 全部檔案，逐檔讀取內容與 `claimed_at`。
2. 時間正規化：先以 regex 剝除字串結尾的括號註記（`（…）` 或 `(...)`，例如地區名後綴），再用 ISO 8601 解析。
3. 解析失敗者歸類 `unparseable`：只進報告、不搬移、不得視為已超門檻。

## 2. 三道閘判定（每檔依序評估，結果全記錄）

- 閘 A 時間：解析成功且 `now - claimed_at > stuck_hours`。
- 閘 B 內容：全文比對完成標記集合，任一命中即判「已完成殘留」。
- 閘 C 結果：先以版本庫 tree 清單（或等效的一次性全量列舉）建立 `done/` 的 task_id 索引集合；該檔 task_id 在集合中即判「已有結果」。
- 分類：
  - A 不過 → `active`（不動）
  - B 命中 → `residual-with-marker`（不動）
  - C 命中 → `residual-with-result`（不動）
  - A 過且 B、C 皆未命中 → `stuck`（候選搬移）
  - 解析失敗 → `unparseable`（不動、需通報）

## 3. 乾跑清單

執行任何搬移前，先輸出清單（表格或 JSON）：每檔一行，欄位＝task_id、claimed_at 原字串、解析後時間、三閘結果、分類、預定動作。`dry_run=true` 時到此為止。

## 4. 執行搬移

1. 候選數 > `move_cap`，或候選數 > 過去 7 日平均的 5 倍：停止執行，先通報（大量候選通常意味判定邏輯出錯）。
2. 逐件搬移 `stuck` 檔案到 `pending/`；目標已有同名檔案時，該件跳過並通報，禁止覆蓋。
3. 每件寫一行稽核紀錄：task_id、原路徑、新路徑、三閘結果、執行時間。

## 5. 輸出

- `report`：各分類計數（active／residual-with-marker／residual-with-result／stuck／unparseable）、實際搬移清單、跳過清單與理由。
- 稽核紀錄檔路徑固定，逐輪 append，不覆寫舊紀錄。

## 6. 驗收（fixture 自測）

建一組 fixture 目錄，含下列五檔，跑一次 dry_run + 一次真執行，比對預期：

| 檔案 | 構造 | 預期分類 | 預期動作 |
|---|---|---|---|
| F1 | claimed_at 72h 前，檔頭有完成標記 | residual-with-marker | 不動 |
| F2 | claimed_at 72h 前，無任何標記；done/ 有同 task_id 結果 | residual-with-result | 不動 |
| F3 | claimed_at 72h 前，無標記；done/ 無結果 | stuck | 搬回 pending/ |
| F4 | claimed_at 1h 前，無標記；done/ 無結果 | active | 不動 |
| F5 | claimed_at 字串帶 `（地區名）` 後綴、1h 前 | active（須解析成功） | 不動 |

五檔全符預期才算實作合格；任一不符，修到全符為止。

## 7. 禁止事項

- 不得以單一訊號（僅認領時間）決定搬移。
- 不得以格式檢查（閘 B）取代結果檢查（閘 C）：舊格式殘留沒有標記，B 必漏，C 才是充分條件。
- 不得覆蓋 pending/ 既有檔案；不得在解析失敗時預設「很舊」。

## 8. 基準案例摘要（2026-10-22／23）

- 事故一：僅用時間規則，52 件已完成任務被判卡單；搬回寫入因 pending/ 已有同名歸檔存根回 422 全數被拒，未釀成覆蓋。事後查：該 52 件在 claimed/ 的殘留副本皆有完成標記。
- 事故二：加了內容檢查後，13 件舊格式殘留（無標記）穿過檢查被判卡單；因 API 速率限制 403 未執行成功。該 13 件在 done/ 皆有結果。
- 同場地雷：claimed_at 帶地區後綴 `（鳳凰城）` 使 ISO 解析失敗，險些誤判正常單。
- 定版即本文件：時間正規化＋內容閘（必要條件）＋done 索引閘（充分條件）＋乾跑與限量。
