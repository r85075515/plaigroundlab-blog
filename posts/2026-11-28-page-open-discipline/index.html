借來的登入態要收尾：自動化開頁登記與自關紀律

給你的 AI：本篇另備乾淨 Markdown 的 agent 版，讀了就能照著做——中文版・English

前段：寫給人看的故事

多條自動化工作線共用同一個已登入的瀏覽器，起初大家都覺得方便：登入態現成、頁面隨開隨用。幾週下來，瀏覽器裡累積了一堆沒人認領的殘留頁——實驗頁、商品頁、查詢頁混在手動使用的頁面中間，分不清哪一頁是誰開的、哪一頁還在用、哪一頁關掉會出事。最後的狀態是：每一頁看起來都可能是重要的，於是沒有一頁敢關，混雜本身變成了風險。

問題不在有人忘了關頁，而在開頁的那一刻就沒有留下任何紀錄。沒有登記，就沒有所有權；沒有所有權，收尾的人只能猜——猜錯了關掉還在用的頁，猜對了也只是運氣。借來的登入態尤其如此：那是別人的工作階段，自動化只是借用，借東西要登記、要用完歸還，這是基本紀律，不是進階工程。

從那之後，開頁紀律定版：自動化一律開在專用視窗（長期改用專用設定檔），不借用手動視窗；開頁當場登記視窗與分頁識別、網址與任務編號；任務結束，自己開的頁自己關；要保留，必須當場寫明理由與期限；常駐頁另有登記白名單，受保護永不自動關閉。

這篇的定版處置分三段。登記：沒有登記的自動化頁面視為所有權不明——不準直接關，先補登記、查明歸屬再處置。自關：登記在自己名下、任務已結束、又沒有有效留置理由的頁，由開頁者自行關閉，不留給別人收。保護：白名單常駐頁與手動視窗整窗不碰；留置可以，但理由與期限缺一不可，期限到了就關閉並回報，不準無限期躺著。

後段把整套判定寫死：六種處置代碼與優先序、登記欄位、留置成立條件與逾期的處置。任何人（或任何 AI）拿到一個瀏覽器頁面情境，都能給出唯一處置，不靠猜。

以下為完整 runbook

1. 三個機制：專用視窗、開頁登記與自關

  • 專用視窗：自動化開頁一律開在專用視窗，長期作法是專用設定檔，與手動使用的視窗完全分家。手動視窗整窗不碰——哪怕裡面混進一頁看似自動化的頁，也不從手動視窗裡挑頁關。
  • 開頁登記：開頁的當場就登記，不準事後回憶補寫。登記欄位寫死四項：視窗識別、分頁識別、網址、任務編號。缺任一項，該頁視為未登記。
  • 自關：任務結束時，開頁者盤點自己登記名下的頁面逐頁處置。自己開的自己關，不把殘留留給下一個使用者、也不留給定期掃除去猜。

2. 留置與白名單

  • 留置：任務結束後仍要保留某頁，必須在登記上加註保留理由與保留期限，兩項齊備才成立有效留置。期限未到，照留置保留；期限一到，留置失效。
  • 白名單：常駐頁——例如登入頁、信箱、文件與工作後台類頁面——另有登記白名單。白名單頁受保護，永不自動關閉，也不因任何留置期限到期而被關。
  • 作用中保護：手動視窗的作用中頁面若屬白名單，該手動視窗整窗受保護；本來手動視窗就整窗不碰，這條只是再加一層明文。

3. 判定代碼與優先序

對每個頁面情境依序檢查，取第一個成立的代碼：

  1. P 保護不關：頁面在常駐白名單上，或頁面位於手動視窗 → P，永不自動關閉，維持原狀。
  2. E 逾期留置：頁面有有效留置登記，但保留期限已經屆滿 → E，關閉該頁並回報留置逾期，不再保留。
  3. R 有據留置：頁面有登記、任務已結束，保留理由與保留期限兩項齊備且期限尚未屆滿 → R，照留置保留至期限，登記上註明理由與期限。
  4. C 結束自關：頁面有登記在某任務名下、該任務已結束，且沒有有效留置（未加註理由或期限，或兩者皆無） → C，由開頁的任務自行關閉。
  5. U 未登記待認領：頁面查無完整登記（四欄位缺任一項），所有權不明，且不屬 P → U，不準直接關閉，先補登記、查明歸屬，再照本規格重新判定。
  6. W 進行中續用：頁面有完整登記、所屬任務尚未結束且正在使用 → W，維持開啟，待任務結束時再照 E／R／C 處置。

4. 證據規則

  • 登記只認當場紀錄：開頁當場寫下的登記表是唯一依據；事後憑記憶宣稱「那頁是我開的」不算登記，照 U 處理。
  • 所有權只認登記：關頁的權限跟著登記走。沒有登記，就沒有「確定可以關」的依據，哪怕那頁看起來再像殘留。
  • 留置只認兩項齊備：理由與期限缺任一項，留置不成立，照 C 處理，不接受口頭說「之後還要用」。
  • 白名單只認登記名單：頁面類型看起來像常駐頁、但不在白名單登記名單上，不享 P 保護，照其登記與任務狀態判定。

5. 誠實邊界

  • 不確定就不關：任何一頁的歸屬或用途查不清楚，預設是 U 補登記查明，不是先關了再說。關錯一頁還在用的頁，代價遠高於多留一頁一天。
  • 掃除不擴權：定期掃除只能處置登記明確、照本規格判定為 C 或 E 的頁；U 與 P 永遠不在掃除的關閉範圍內。
  • 借用要註明範圍：借用他人登入態的工作線，任務單上要明載借用範圍與收尾方式；借用結束，收尾責任在借用者，不在登入態的持有人。
  • 專用設定檔是長期解：專用視窗只是過渡；殘留問題的結構解是自動化改用專用設定檔，讓手動與自動化的頁面從來源就分家。

6. 常見錯誤清單

  • 開頁不登記：當下省十秒，收尾時全隊陪著猜每一頁的歸屬——登記的成本在開頁時付，猜的成本在收尾時連本帶利還。
  • 從手動視窗挑頁關：看到手動視窗裡有一頁像自動化開的就順手關掉；手動視窗整窗不碰，沒有例外挑頁。
  • 留置只寫理由不寫期限：「之後還要用」不是留置，是無限期殘留的藉口；沒有期限的留置照 C 關閉。
  • 看起來像殘留就關：頁面舊、標題陌生、開了很久，都不是所有權證據；沒有登記佐證，一律先照 U。
  • 把白名單當感覺：覺得某頁「應該是常駐的」就跳過盤點；白名單以登記名單為準，名單外照常判定。
