From 20s Polling to 73.8ms Push Wakeups: A $0 Three-Tier Self-Healing Agent Bus

For your AI: this post ships with a runnable, desensitized agent edition — English · 中文版

1. Why 20-Second Polling Breaks Down Across Multi-Agent Workflows

When autonomous coding, security, and coordination agents collaborate across cloud VMs and a local workstation, polling a GitHub thread every 20 seconds fails on three fronts at once:

  • Sluggish feedback loops: Two review turns easily lose a full minute just waiting for poll boundaries.
  • Sleep drops and wasted cycles: Laptop sleep breaks ephemeral loops; endpoints without strict If-None-Match burn quota while nothing happens.
  • Single-pool quota stalls: When a headless runner is pinned to a single LLM quota bucket, hitting a 429 stalls execution until the 5-hour window resets.

Our constraint was strict: $0/month extra infrastructure spend. Using Cloudflare Workers Free Tier, KV, an isolated cloudflared tunnel, and zero-dependency Python stdlib managed by macOS launchd, we cut wakeup round-trip latency down to 73.8ms with three self-healing fallback tiers and cross-pool quota failover.

1. Cloudflare Worker: 8s Inline Push with Auto KV Cleanup

// mailbox-worker.js (Cloudflare Workers + KV excerpt)
const PUSH_TIMEOUT_MS = 8000;

async function deliverOrQueue(env, mailbox, id, msg) {
  const pushUrl = env[`${mailbox.toUpperCase()}_PUSH_URL`];
  const pushKey = env[`${mailbox.toUpperCase()}_PUSH_KEY`];
  if (!pushUrl || !pushKey) {
    await env.MAILBOX.put(`msg:${mailbox}:${id}`, JSON.stringify(msg), { expirationTtl: 86400 });
    return { result: 'queued_kv', status: null };
  }

  try {
    const res = await fetch(pushUrl, {
      method: 'POST',
      redirect: 'manual',
      signal: AbortSignal.timeout(PUSH_TIMEOUT_MS),
      headers: {
        'content-type': 'application/json',
        'authorization': `Bearer ${pushKey}`,
        'x-fleet-mailbox-id': id,
      },
      body: JSON.stringify(msg),
    });
    if (res.ok) {
      return { result: 'delivered', status: res.status };
    }
  } catch (_) {}

  await env.MAILBOX.put(`msg:${mailbox}:${id}`, JSON.stringify(msg), { expirationTtl: 86400 });
  return { result: 'queued_fallback', status: 502 };
}

2. Zero-Dependency Loopback Receiver + Atomic Wake Signal

# push_receiver.py (Python 3 stdlib only)
import hmac
import json
import os
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
from pathlib import Path

STATE_DIR = Path(os.path.expanduser("~/.agent-receiver/state"))
PUSH_KEY = Path(os.path.expanduser("~/.secrets/push_key")).read_text(encoding="utf-8").strip()
SEEN_IDS = set()

class Handler(BaseHTTPRequestHandler):
    def do_POST(self):
        if self.path != "/push":
            return self._json(404, {"ok": False, "error": "not_found"})
        auth = (self.headers.get("Authorization") or "").split(None, 1)
        if len(auth) != 2 or auth[0].lower() != "bearer" or not hmac.compare_digest(auth[1], PUSH_KEY):
            return self._json(401, {"ok": False, "error": "unauthorized"})

        length = int(self.headers.get("Content-Length", "0"))
        if length <= 0 or length > 16384:
            return self._json(400, {"ok": False, "error": "invalid_payload_size"})

        payload = json.loads(self.rfile.read(length).decode("utf-8"))
        msg_id = (self.headers.get("x-fleet-mailbox-id") or payload.get("id") or "").strip()
        if msg_id and msg_id in SEEN_IDS:
            return self._json(200, {"ok": True, "duplicate": True, "id": msg_id})

        STATE_DIR.mkdir(parents=True, exist_ok=True)
        tmp = STATE_DIR / "wake.signal.tmp"
        tmp.write_text(json.dumps(payload, ensure_ascii=False) + "\n", encoding="utf-8")
        os.replace(tmp, STATE_DIR / "wake.signal")  # atomic swap avoids partial reads
        if msg_id:
            SEEN_IDS.add(msg_id)
        return self._json(200, {"ok": True, "duplicate": False, "id": msg_id})

    def _json(self, status: int, obj: dict):
        raw = json.dumps(obj).encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(raw)))
        self.end_headers()
        self.wfile.write(raw)

ThreadingHTTPServer(("127.0.0.1", 18792), Handler).serve_forever()

5. Three Real Production Pitfalls & Fixes

  1. cloudflared tunnel route dns silently attached the CNAME to an older tunnel: Running cloudflared tunnel route dns <new-name> <host> on a host that already has ~/.cloudflared/config.yml reads the old default tunnel ID. Always invoke cloudflared tunnel --config ~/.cloudflared/agent-hook.yml route dns --overwrite-dns <NEW_UUID> <host> explicitly.
  2. Cloudflare Edge WAF returned HTTP 403 to Python urllib: While Cloudflare Workers and curl immediately saw HTTP 200, default Python urllib.request hit <HTTPError 403: 'Forbidden'>. Standardizing fallback probes on curl with an explicit User-Agent eliminated the discrepancy.
  3. GIT_EDITOR=false broke headless git rebase --continue: Even with -c core.editor=true, background runners threw error: there was a problem with the editor 'false' because GIT_EDITOR env takes precedence. Injecting env["GIT_EDITOR"] = "true" in the runner subprocess wrapper—and testing against a temporary bare+worker repo conflict—fixed it permanently.
